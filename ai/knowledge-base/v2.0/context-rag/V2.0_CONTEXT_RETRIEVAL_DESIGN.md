# V2.0 Context Retrieval / RAG Design

> 定位：V2.0 Context / Retrieval 能力的架构说明。专业执行约束以 `ai/rules/CONTEXT_RETRIEVAL_CONTRACT_V1.0.md` 为准。

## 1. 目的

V2.0 已有 `Query → Retrieval → Context Assembly` 能力抽象。本设计将其明确为统一 Context Layer，并允许使用 RAG 作为实现方式。

RAG 不是独立业务阶段，也不是新增业务 Agent。

## 2. 在 V2.0 中的位置

```text
User / Trigger
↓
Runtime
↓
Project Context Load
↓
Context Retrieval / RAG
↓
Context Validation
↓
Context Assembly
↓
Capability / Agent / Model / Tool / MCP / Skill
↓
Execution
↓
Verification / Audit / Trace
```

## 3. 与现有能力关系

- Knowledge Base：负责承载可复用知识与项目资产；
- Knowledge Agent：负责沉淀、整理、更新知识；
- Context Retrieval：负责执行时发现和选择知识；
- Context Assembly：负责形成当前执行所需上下文；
- Runtime：负责调度与持久化；
- Agent：负责使用上下文完成专业任务。

## 4. 不是所有任务都必须做 RAG

只有当任务依赖已有知识、历史资产、项目上下文、规则或外部资料时，Runtime 才必须执行 Retrieval。

对完全自包含、无需外部上下文的任务，可以声明 `RETRIEVAL_NOT_REQUIRED`。

## 5. 检索原则

```text
Current Effective Rule
→ Current Project Context
→ Current Project Assets
→ Historical Project Knowledge
→ Authorized General Knowledge
```

必须优先保证有效性、适用范围、权限和来源可信度，而不是单纯追求相似度。

## 6. 重点数据

Context Retrieval 应形成独立 Execution Evidence，包括：

- query
- retrieval mode
- candidate / selected context
- source / version
- ranking / reranking
- context hash
- retrieval timestamp
- permission scope

## 7. 当前落地状态

本版本完成：

- Context Retrieval Contract；
- RAG 与 Context Layer 的关系定义；
- Retrieval / Assembly / Permission / Provenance / Freshness 约束；
- 与 Runtime、Knowledge Agent、Process Agent、Audit 的边界定义。

后续可独立实现 Vector Store、Hybrid Search、Reranker、Embedding Provider 等 Runtime Capability，但不得反向改变上述基础 Contract。
