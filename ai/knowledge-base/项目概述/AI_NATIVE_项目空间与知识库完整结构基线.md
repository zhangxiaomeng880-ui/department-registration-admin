## 三、核心边界

1. 1.0 与 2.0 独立管理。
2. 项目文档与知识库严格分离。
3. 项目基线、迭代、决策、执行、验证分别管理。
4. 历史版本保留，不覆盖历史。
5. 每个重要对象保持固定溯源。
6. 当前状态必须有唯一有效基线。
7. 项目事实不会自动成为知识；必须经过提炼与确认后进入知识库。
8. 跨版本引用必须保留来源，不直接覆盖原版本。
9. 无法确认归属时不得擅自迁移。
10. 迁移必须先建立归属映射，再执行复制、验证、删除源文件。

## 四、项目迭代

过去 Git 中的 v1.0、v1.1、v1.2、v1.3、v2.0 是历史存储结构，不等同于今天定义的完整项目迭代模型。

现在正式将项目迭代定义为：

原基线 → 问题/变化 → 变更原因 → 变更内容 → 执行 → 验证 → 新基线。

历史版本不得因为新结构建立而丢失。

## 五、溯源闭环

知识 → 项目基线 → 执行 → 验证 → 迭代 → 新基线 → 可复用经验 → 知识沉淀。

## 六、真实性要求

不得自行扩展任务范围，不得编造历史记录、文档、执行结果或验证结果。所有“已完成”状态必须有实际执行证据；未执行必须明确标记未执行。
