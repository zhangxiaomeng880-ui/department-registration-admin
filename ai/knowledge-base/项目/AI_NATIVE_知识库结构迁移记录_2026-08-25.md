# AI Native 知识库结构迁移记录

**目标：按 2026-08-25 正式确定的整体知识库结构重新归档**

## 迁移原则

1. 先确认历史文件归属，再执行迁移。
2. 使用原 Git Blob SHA 建立目标路径，保持文件内容不变。
3. 目标路径完成后再删除旧路径。
4. 单次提交完成结构变更，保留 Git 历史提交作为溯源。
5. 不删除任何文件内容；仅调整路径。

## 归属判断

- `STAGE_DOCUMENT_INDEX.md`：整体知识库项目级索引 → `知识库/项目`。
- `v1.0`：AI Native 1.0；其中 Project OS、项目目录说明属于项目，设计/执行/合规/工作流规则属于 1.0 知识库，Project Evolution 属于 1.0 项目迭代记录。
- `v1.1`、`v1.2`、`v1.3`：历史上属于 1.0 演进；OS 文档归入 1.0 项目迭代，V1.2 Learnings 归入 1.0 知识库方法论。
- `v2.0`：属于 AI Native 2.0；当前三个文档均为 2.0 的操作系统、规划模型或数据资产模型，因此归入 2.0 知识库，而不是伪装成已经实际执行的项目产物。

## 重要事实

历史 Git 结构原本以 `v1.0/v1.1/v1.2/v1.3/v2.0` 为主要目录维度。当时尚未正式建立“项目迭代”这一独立管理维度。本次迁移是将历史结构映射到今天正式建立的“版本 + 项目/知识库 + 基线/迭代/决策/执行/验证”模型，而不是声称该结构历史上已经存在。

## 验证要求

迁移完成后必须验证：
- 新路径全部存在；
- 新路径 Blob SHA 与源文件一致；
- 原路径全部移除；
- Git 分支指向新的提交；
- 无新增重复内容；
- 迁移记录和结构基线均可追溯。
